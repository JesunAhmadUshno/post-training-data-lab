# BUILD-SPEC: P28 Level 2, synthetic generation, filtering, mixture study

Written before any Build code, per the house spec-first rule. All
expected values below are computed from the design in this file.
Code that disagrees with this spec is wrong, not the spec.
All data in this level is synthetic, generated by this project,
and labelled synthetic in every file. No real data is used,
downloaded, or claimed.

## Contrast stated before running (mixture study design)

- Mixture A: the raw generated mix, unfiltered, exactly as
  generated (536 records). It contains every flawed tier below.
- Mixture B: the same raw records passed through the Level 1
  Learn pipeline in its fixed order (exact dedup, near dedup at
  instruction token Jaccard 0.8, quality filters, decontamination
  against the 2 Learn benchmark prompts). Expected 192 records.
- The named difference is filtering only. Same generator, same
  model code, same smoothing, same held-out eval set for both.
- Downstream task (proxy, named as a proxy): predict the category
  of an instruction. Model: multinomial Naive Bayes over
  instruction tokens, standard library only, alpha 1.0, out of
  vocabulary tokens skipped, log prior from class record counts,
  ties broken by first category in alphabetical order.
- Metric: accuracy on the held-out eval set (correct over 80),
  overall and per category.

## Generator design (seeded, deterministic)

Seed 42 (random.Random shuffles the topic token assignment pool;
generation order and counts are fixed by the loops below, so the
hand counts in this spec do not depend on the shuffle).

Categories in fixed order: code, factual, language, writing.
Signal verbs per category (two each, alternating by round):
code: implement, debug. factual: explain, describe.
language: translate, render. writing: write, compose.

Clean instruction template (5 tokens): verb, a unique topic token
(topicNNN, unique across all training records), in, simple, terms.
Clean output templates are per category, at least 2 tokens, and
name the topic token. Clean labels are the true category.

Tiers, in generation order:

1. Clean: 48 rounds, round-robin over the 4 categories, so 48 per
   category, 192 total. Ids s001 to s192.
2. Exact duplicates: copies of clean records s001 to s024 (6 per
   category in round-robin order), new ids d001 to d024, identical
   instruction, output, and label. Count 24.
3. Near duplicates: copies of clean records s025 to s048 (6 per
   category), new ids n001 to n024, with one token, please,
   appended to the instruction. Jaccard oracle below. Count 24.
4. Low-quality poison: for each true-signal category X in fixed
   order, 72 records whose instruction follows the clean template
   with X signal verbs (36 per verb) and unique topic tokens, whose
   output is the single token unknown (1 token), and whose label
   is the next category after X in the fixed order (code to
   factual, factual to language, language to writing, writing to
   code). Ids p001 to p288. Count 288. These records are
   deliberately flawed in two ways at once: a stub output and a
   label that does not match the instruction signal.
5. Contaminated: 8 records. x001 to x004 use the benchmark prompt
   What is the capital of Canada as the instruction, label
   writing, and a distinct long output each. x005 to x008 use
   State the theorem of Pythagoras, label code, distinct long
   output each. Outputs have at least 2 tokens, so these pass the
   quality filters and can only leave at decontamination (or as
   near duplicates of an earlier copy, see stage counts).

Raw total: 192 + 24 + 24 + 288 + 8 = 536 records.
Raw label counts: each label gets 48 clean + 6 exact + 6 near +
72 poison = 132, plus contaminated 4 for writing and 4 for code,
giving code 136, factual 132, language 132, writing 136.
Templated records per label are 132 for every label (contaminated
records are not templated), so the shared template tokens in,
simple, terms each occur 132 times under every label.

## Hand-computed filtering stage counts (Learn pipeline reuse)

The Build study reuses the Learn pipeline functions unchanged
(exact_dedup, near_dedup, quality_filter, decontaminate, tokens,
jaccard from level-1-learn/pipeline.py).

1. Raw: 536.
2. Exact dedup removes the 24 exact copies (originals come first
   in generation order). Left: 512.
3. Near dedup: the 24 near copies each have Jaccard 5 over 6,
   which is 0.833333, against their original (5 shared tokens,
   union 6), at or above 0.8, so all 24 are removed. Clean records
   against each other share at most verb, in, simple, terms (4
   over a union of 6, 0.667) for the same verb, or in, simple,
   terms (3 over 7, 0.429) otherwise, so no clean record is
   removed. Poison records share the same template bounds, so no
   poison record is removed here. Contaminated copies of the same
   prompt have identical instruction token sets (Jaccard 1.0), so
   per prompt the first copy is kept and the other 3 are removed:
   6 removed. Stage removes 24 + 6 = 30. Left: 482.
4. Quality filters (instruction at least 3 tokens, output at
   least 2 tokens): every poison record has a 1 token output, so
   all 288 are removed. Clean, duplicate survivors, and
   contaminated survivors all pass. Left: 194.
5. Decontamination: the 2 contaminated survivors (x001, x005, the
   first copy of each prompt) match the 2 benchmark prompts
   exactly and are removed. Left: 192, exactly the clean ids
   s001 to s192, 48 per category.

## Hand-computed model expectations

Signal verb counts under the true label in mixture B: each verb
appears in 24 clean records of its category and in no other
record, so a clean signal verb votes only for its true category.
Shared tokens are balanced (48 per label in B). Eval topics are
out of vocabulary and skipped. Prediction for B: every eval
record is predicted as its true category. Expected B accuracy
80 over 80, which is 1.0, 20 over 20 in each category. This is a
toy separable template task by design; the README names that as
a deduction, not a discovery.

Signal verb counts in mixture A: under the true label, each verb
has 24 clean + 3 exact copies + 3 near copies = 30 records. Under
the poison label (the next category), the same verb has 36 poison
records. The poison count exceeds the true count for every verb,
the shared templated tokens are balanced at 132 per label, and
class token totals differ only through the 8 contaminated
records (writing 684 instruction tokens, code 680, factual and
language 660 each, against a shared vocabulary). The verb term
therefore decides every templated eval record in favour of the
poison label, which is the next category in the fixed order.
Prediction for A: every eval record is predicted as the next
category after its true one. Expected A accuracy 0 over 80,
which is 0.0, 0 over 20 in each category, with the full confusion
pattern cyclic (code to factual, factual to language, language
to writing, writing to code). If the measured result differs
from this prediction, the run is investigated, not adjusted.

## Naive Bayes toy oracle (hand-computed)

Training: (red apple, fruit), (red cherry, fruit),
(blue truck, vehicle). Alpha 1.0. Vocabulary size 5 (red, apple,
cherry, blue, truck). Fruit token total 4, vehicle token total 2.
Priors: fruit 2 over 3, vehicle 1 over 3.

Predict red apple:
- fruit: log(2/3) + log(3/9) + log(2/9) = -0.405465 - 1.098612
  - 1.504077 = -3.008154.
- vehicle: log(1/3) + log(1/7) + log(1/7) = -1.098612 - 1.945910
  - 1.945910 = -4.990432.
Prediction: fruit.

Predict blue truck:
- fruit: log(2/3) + log(1/9) + log(1/9) = -0.405465 - 2.197225
  - 2.197225 = -4.799914.
- vehicle: log(1/3) + log(2/7) + log(2/7) = -1.098612 - 1.252763
  - 1.252763 = -3.604138.
Prediction: vehicle.

Tests assert both predictions and both winning scores to 1e-6
relative tolerance against these hand values (scores computed in
the test from the same hand fractions, not copied from the code).

## Held-out eval set (synthetic, labelled synthetic)

80 records, ids e001 to e080, 20 rounds round-robin over the 4
categories (20 per category, 10 per signal verb), clean template
and clean outputs, topic tokens evaltopicNNN, which never occur
in training. Eval records are never part of either mixture.

## Results file

run_build.py writes results_build.json (stage counts, removed
ids per stage, mixture sizes and label counts, eval accuracy
overall and per category and confusion counts for A and B,
generator and eval counts, seed), plus synthetic_data.jsonl (the
536 raw records) and synthetic_eval.jsonl (the 80 eval records),
each record carrying its synthetic label, source, and license.
All three files must be deterministic and results_build.json
must be byte-identical across two runs (sha256 checked).
